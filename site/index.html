JavaFX desktop application

Run a small gym from one clear workspace.

GymFlow connects Owners and Members through one JavaFX desktop application backed by shared Supabase authentication and data services.

View source Run locally

Role-based workflows

One shared system for Owners and Members.

Owner

Members and Memberships

Create and search Member profiles, reset credentials, record renewal payments, and manage access periods.

Owner

Finances and dashboard

Review income, add operating expenses, and monitor six live Member, access, visitor, and all-time financial summaries.

Owner

Visits and exports

Review attendance, correct timestamps with a reason, and export current Member, Payment, or Visit results to CSV.

Owner

Announcements and Owners

Publish or withdraw notices and provision co-Owners through protected administrative actions.

Member

Membership and attendance

Review access periods and renewal guidance, then check in and out when a Membership is currently valid.

Member

Training and account

Track Workouts, history, and body mass; read notices; and manage personal profile and password details.

Local review

Start with disposable Supabase data.

GymFlow targets Java 25 on Windows x64, Linux x64, macOS x64, and macOS ARM64. Its release JARs are clients and still require a configured backend; they are not standalone databases. Docker and Node/npm are needed for disposable local review, but not when a maintainer configures the JAR for the deployed hosted backend.

Open the complete Windows and macOS/Linux quick start.

1

Install a matching-architecture Java 25 JDK, Node/npm, and Docker Desktop.

2

Clone the source, run npm install, then start and reset local Supabase.

3

Serve the protected Edge Function in a second terminal.

4

Run ./gradlew runLocal --no-watch-fs and use a seeded test account.

Testing and operations

Built to be checked.

Backend checks

pgTAP database tests, Edge Function tests, and local integration checks cover authorization, constraints, and shared workflows.

Desktop and packaging

Gradle runs JUnit, Checkstyle, rendered UI checks, and verifies four platform-specific JARs in local and CI workflows.

Operations

CI repeats integration verification, rotating local logs capture sanitized failures, and uptime monitoring checks this Pages site every six hours.
